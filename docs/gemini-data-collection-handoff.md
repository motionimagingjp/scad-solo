# SCAD-SOLO 店舗データ収集 引き継ぎ書(Gemini用)

## これは何のためのタスクか
「SCAD-SOLO」は一人飲みの店を探すアプリです。トップ画面「今夜の3軒」は、
現在地から近い順にDBの店舗を検索して3軒ずつ表示します(ランダム抽選ではない)。
現状はデモ(架空)データしか入っておらず、実店舗データを投入する必要があります。
このタスクは、指定エリアの実在する居酒屋・ワインバー・立ち飲み屋を検索して
リスト化することです。

## 探してほしい店の条件
- **実在し、現在も営業している店**であること(閉業店は不可)
- ジャンル: 居酒屋・ワインバー(ワイン店)・立ち飲み屋 が中心
- 「一人でも入りやすい」ことが分かる店を優先(カウンター席がある、一人客の
  口コミがある、等)
- 出典(公式サイト・食べログ・Googleマップのレビュー等のURL)を確認できた店だけを
  採用すること。**確証が持てない店は無理に載せず除外する**(実在しない店を
  作ってしまう=ハルシネーションが一番避けたい失敗)

## 対象駅とノルマ(Phase 0)
以下15駅、各駅15〜20軒を目標にしてください。

新宿・渋谷・池袋・上野・秋葉原・五反田・北千住・川崎・横浜・立川・錦糸町・高円寺・
水道橋・新橋・恵比寿

駅ごとに1ファイル(下記フォーマット)で作成してください。

## 【重要】店名の使い回し禁止(必読)

複数駅のデータで、**同じ店名パターン(「ワインバル 八十郎」「日本酒スタンド 蔵元屋」
「立呑み 魚金」等)を駅名だけ差し替えて繰り返し使う**事例が発見されました。
実際にその都道府県に5店舗以上ある全国チェーンでない限り、こうした偶然の一致は
起こりません。**「このジャンル(クラフトビール専門店・ウイスキーバー・ご当地
居酒屋等)の穴を埋めるために、他の駅で使った店名や似た店名を別の駅でも使う」
ことは絶対にしないでください**。1駅ごとに完全に独立して新しく検索し、その駅で
実際に確認できた店だけを載せること。同じジャンルの店が見つからない駅は、
無理に埋めず件数が少なくても構いません。

## 大手チェーンの判定ルール

個別に列挙したチェーン(日高屋、晩杯屋、鳥貴族、磯丸水産、築地銀だこハイボール
酒場等)に加えて、**同一都道府県内に5店舗以上存在するブランドは、個人店・
ローカルチェーンではなく「大手チェーン」とみなして除外**してください
(全国区でなくても、1つの都道府県に5店舗以上あれば規模的にチェーンと判断)。

## 出力フォーマット(重要・厳守)

DBへの取り込みスクリプト(`scripts/import-spots.ts`)がこのJSON形式をそのまま
読み込みます。**この形式から外れないでください**(緯度経度は不要。住所文字列から
このスクリプト側でジオコーディングします)。

```json
[
  {
    "name": "店名(正式名称)",
    "address": "住所(番地まで正確に。緯度経度は不要)",
    "nearestStation": "最寄駅名(例: 渋谷駅)",
    "tagline": "一言の推し文(20〜30字程度。カードに表示される決め手の一言)",
    "subCategories": ["立ち飲み", "日本酒"],
    "hasCounterSeat": true,
    "senberoAvailable": false,
    "soloFriendliness": 8,
    "sourceNote": "出典URL(食べログ/Googleマップ/公式サイト等)"
  }
]
```

### 各フィールドの説明

| フィールド | 必須 | 説明 |
|---|---|---|
| `name` | ○ | 店の正式名称。**住所やURLが正しくても店名だけ誤変換されるケースがある**(例: 新宿の実在店「ベルク」を「ベルゴロド(BERG)」と誤記した事例あり)。出典ページに実際に書かれている表記をそのまま使うこと |
| `address` | ○ | 住所(番地まで)。ジオコーディングに使うので正確に |
| `nearestStation` | ○ | 対象駅名(集計・ノルマ管理用のキー) |
| `tagline` | 推奨 | 「一人客が7割のカウンター」のような一言。誇張・創作せず、レビュー等の実際の
特徴から作ること |
| `subCategories` | 任意 | 下記「タグの語彙」から当てはまるものだけを選ぶ(配列)。当てはまらなければ空配列 `[]` |
| `hasCounterSeat` | 任意 | カウンター席があると確認できた場合のみ `true`。不明なら省略(省略時はアプリ側で`true`扱いになるため、**カウンターが無いと分かっている場合は必ず`false`を明記**) |
| `senberoAvailable` | 任意 | 「せんべろ」(少額で酔える)と言えるなら `true` |
| `soloFriendliness` | 任意 | 1〜10の主観スコア。一人客への配慮(カウンター、少量メニュー、一人歓迎の口コミ等)が多いほど高く |
| `sourceNote` | 推奨 | 確認した情報源のURL。人力レビュー時の裏取りに使うので必ず入れてほしい |

`category` フィールドは省略してください(全店 `SOLO_NOMI` 扱いになります)。

### タグの語彙(`subCategories`)
アプリのフィルターと1対1で対応しているので、**この一覧以外の言葉は使わない**でください。
- `カウンター席` は使わない(専用の `hasCounterSeat` フィールドを使う)
- `せんべろ` も使わない(専用の `senberoAvailable` フィールドを使う)
- `立ち飲み` / `日本酒` / `ワイン` / `ビール` / `女性ひとり歓迎`
- (`カラオケ` / `サウナ` はこのタスクの対象外なので基本的に使わない)

## 進め方の推奨
1. 駅ごとに検索(例: 「渋谷駅 一人飲み 穴場」「渋谷 立ち飲み カウンター」等)
2. 候補が出典付きで確認できたら上記フォーマットで1件追加
3. 15〜20件たまったら駅名でファイルを分けて出力(例: `spots-shibuya.json`)
4. 迷ったら「載せない」を選ぶ(false positiveよりfalse negativeの方が被害が小さいため)

## 出来上がったら
駅ごとのJSONファイルをこちらに戻してください。Claude側で
`scripts/import-spots.ts` を使ってジオコーディング→DB投入します。
