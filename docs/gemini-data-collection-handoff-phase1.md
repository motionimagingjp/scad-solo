# SCAD-SOLO 店舗データ収集 引き継ぎ書(Gemini用・Phase 1)

Phase 0(新宿・渋谷・池袋・上野・秋葉原・五反田・北千住・川崎・横浜・立川・
錦糸町・水道橋・新橋・恵比寿の14駅・194件、高円寺は未収集)に続く追加バッチ。
探す条件・出力フォーマットはPhase 0と同じ。**対象駅だけが違います**。

## これは何のためのタスクか
「SCAD-SOLO」は一人飲みの店を探すアプリです。トップ画面「今夜のおすすめ3軒」は、
現在地から近い順にDBの店舗を検索して3軒ずつ表示します(ランダム抽選ではない)。
このタスクは、指定エリアの実在する居酒屋・ワインバー・立ち飲み屋を検索して
リスト化することです。

## 探してほしい店の条件
- **実在し、現在も営業している店**であること(閉業店は不可)
- ジャンル: 居酒屋・ワインバー(ワイン店)・立ち飲み屋 が中心
- 「一人でも入りやすい」ことが分かる店を優先(カウンター席がある、一人客の
  口コミがある、等)
- 出典(公式サイト・食べログ・Googleマップのレビュー等のURL)を確認できた店だけを
  採用すること。**確証が持てない店は無理に載せず除外する**(実在しない店を
  作ってしまう=ハルシネーションが一番避けたい失敗)
- ポータルサイトのまとめ記事に出てくるような無難な店や大規模チェーンではなく、
  酒好き・立ち飲みマニアに評価されているディープな個人店・隠れ家酒場を優先する

## 優先して参照する情報源
- [Syupo(syupo.com)](https://syupo.com/): 酒場ライター塩見なゆ氏による昭和酒場・
  名店専門メディア
- [せんべろnet(1000bero.net)](https://1000bero.net/): 立ち飲み・せんべろ系
  ディープ店のデータベース
- 個人の酒場ブログ・note・SNS: 「〇〇(駅名) 昼飲み 立ち飲み ブログ」等で検索
- 上記に加えて食べログ・Googleマップも引き続き裏取りに使ってよい

## 対象駅とノルマ(Phase 1)
以下10駅、**各駅15軒**を目標にしてください(合計150軒目安)。
利用客が多く、かつ一人飲み文化で知られる駅を優先して選定しています。

東京・神田・有楽町・赤羽・品川・中野・吉祥寺・高田馬場・大宮・蒲田

駅ごとに1ファイル(下記フォーマット)で作成してください。

## 【重要】店名の使い回し禁止(必読)

複数駅のデータで、**同じ店名パターンを駅名だけ差し替えて繰り返し使う**事例が
Phase 0で発見されました。実際にその都道府県に5店舗以上ある全国チェーンで
ない限り、こうした偶然の一致は起こりません。**他の駅で使った店名や似た店名を
別の駅でも使うことは絶対にしないでください**。1駅ごとに完全に独立して新しく
検索し、その駅で実際に確認できた店だけを載せること。同じジャンルの店が
見つからない駅は、無理に埋めず件数が少なくても構いません。

## 大手チェーンの判定ルール

個別に列挙したチェーン(日高屋、晩杯屋、鳥貴族、磯丸水産、築地銀だこハイボール
酒場等)に加えて、**同一都道府県内に5店舗以上存在するブランドは、個人店・
ローカルチェーンではなく「大手チェーン」とみなして除外**してください。

## 出力フォーマット(重要・厳守)

```json
[
  {
    "name": "店名(正式名称)",
    "address": "住所(番地まで正確に。緯度経度は不要)",
    "nearestStation": "最寄駅名(例: 東京駅)",
    "tagline": "一言の推し文(20〜30字程度。カードに表示される決め手の一言)",
    "subCategories": ["立ち飲み", "日本酒"],
    "hasCounterSeat": true,
    "senberoAvailable": false,
    "soloFriendliness": 8,
    "sourceNote": "出典URL(食べログ/Googleマップ/公式サイト等)"
  }
]
```

### 各フィールドの説明

| フィールド | 必須 | 説明 |
|---|---|---|
| `name` | ○ | 店の正式名称。**住所やURLが正しくても店名だけ誤変換されるケースがある**(実例あり)。出典ページに実際に書かれている表記をそのまま使うこと |
| `address` | ○ | 住所(番地まで)。ジオコーディングに使うので正確に |
| `nearestStation` | ○ | 対象駅名(集計・ノルマ管理用のキー) |
| `tagline` | 推奨 | 「一人客が7割のカウンター」のような一言。誇張・創作せず、レビュー等の実際の特徴から作ること |
| `subCategories` | 任意 | 下記「タグの語彙」から当てはまるものだけを選ぶ(配列)。当てはまらなければ空配列 `[]` |
| `hasCounterSeat` | 任意 | カウンター席があると確認できた場合のみ `true`。**カウンターが無いと分かっている場合は必ず`false`を明記** |
| `senberoAvailable` | 任意 | 「せんべろ」(少額で酔える)と言えるなら `true` |
| `soloFriendliness` | 任意 | 1〜10の主観スコア。一人客への配慮が多いほど高く |
| `sourceNote` | 推奨 | 確認した情報源のURL。人力レビュー時の裏取りに使うので必ず入れてほしい |

`category` フィールドは省略してください(全店 `SOLO_NOMI` 扱いになります)。

### タグの語彙(`subCategories`)
アプリのフィルターと1対1で対応しているので、**この一覧以外の言葉は使わない**でください。
- `カウンター席` は使わない(専用の `hasCounterSeat` フィールドを使う)
- `せんべろ` も使わない(専用の `senberoAvailable` フィールドを使う)
- `立ち飲み` / `日本酒` / `ワイン` / `ビール` / `女性ひとり歓迎`

## 進め方の推奨
1. 駅ごとに検索(例: 「神田駅 一人飲み 穴場」「赤羽 立ち飲み カウンター」等)
2. 候補が出典付きで確認できたら上記フォーマットで1件追加
3. 15件たまったら駅名でファイルを分けて出力(例: `spots-tokyo.json`, `spots-kanda.json`)
4. 迷ったら「載せない」を選ぶ(false positiveよりfalse negativeの方が被害が小さいため)

## 出来上がったら
駅ごとのJSONファイルをこちらに戻してください。`data/spots-<station>.json`に
追加し、`app/api/admin/import-spots/route.ts`のimport一覧に追記した上で
デプロイ後にDB投入します(Phase 0と同じ手順)。
